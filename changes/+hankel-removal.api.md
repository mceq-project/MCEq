Hankel-mode 2D databases are no longer read: a 2D file whose `common` group lacks `angular_basis = "legendre"` (this includes `mceq_base_air_2d_v2.h5` and `mceq_model_SIBYLL23E_air_2d_v2.h5` of the v2.0.0 data release) raises a `ValueError` naming the file, and the installed `mceq_db_manifest_v2.yaml` no longer lists those two packages (no `2d` default). Removed with them: `MCEq.driver.results.inverse_hankel_legacy`, `MCEq.operators.secant.secant_coupling_matrix` and its operator caches (a `secant_cache/` directory left in `config.data_dir` can be deleted), the config keys `secant_theta_row_kmax`, `secant_theta_lam_rel`, `secant_theta_w_flat` (`config.secant.row_kmax/lam_rel/w_flat`), the `paths` argument of `build_secant_kernel_ops` (whose first argument is now `l_grid`) and the `oversample_res` argument of `convert_to_theta_space`, whose amplitudes argument is now `modes`. `convert_to_theta_space` returns `(l_grid, amps, theta_range, f_theta)`: the first two entries are the Legendre mode grid and the moments on it, where it returned an oversampled Hankel grid and the interpolated amplitudes; `f_theta` keeps the planar measure `θ dθ`. `MCEq.operators.scattering.screened_coulomb_rate` (the planar rate) is replaced by `screened_coulomb_rate_legendre`. `secant_theta_cap_deg` accepts any value in [0, 90) (was [50, 90)).

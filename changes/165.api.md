2D (Hankel-mode) databases now ship with production defaults:

- ``config.secant_theta_transport`` defaults to ``"auto"``: the sec(theta)
  path-elongation correction is applied to every single-axis ``solve()`` on a
  2D database (numpy/mkl/cuda ETD2 kernels) and falls back to the paraxial
  transport with a warning on the multi-RHS/carousel entry points, where the
  mode coupling is not implemented. ``True`` restores the strict semantics
  (unsupported paths raise); ``False`` disables the correction. 1D databases
  are unaffected.
- ``config.secant_theta_cap_deg`` is a plain float (default 75) clamping the
  sec(theta) growth at the axis angle where the correction stays
  well-conditioned; values must lie in [50, 90). The angle is defined
  relative to the shower axis, like the Hankel modes themselves.
- Legacy database layouts are retired and now fail with an explicit error
  instead of a silent fallback: cross-section tables must carry the
  ``parents`` attribute (not ``projectiles``), 2D ``polarized`` decay
  datasets must declare ``layout='superset'``, continuous losses must be
  split into ``ionization``/``total`` subgroups, and the MCEq 1.2.0 decay
  dataset aliases (``full_decays``/``custom_decays``) are gone. The URQMD
  2D database support is retired with them; the test suite baselines
  against the FLUKA 2D database.

Runtime HE/LE interaction-model blending now works on 2D (Hankel-mode)
databases, applied per kappa mode:

- ``config.restrict_2d_to_fluka`` and the FLUKA-only 2D model restriction
  are removed. On a multi-model 2D database (e.g. SIBYLL23E on the
  high-energy grid + FLUKA20251 on the low-energy grid, both stored as
  48-mode blocks on a common energy lattice), selecting a high-energy
  model together with ``low_energy_extension`` blends the ``(n_k, n_e,
  n_e)`` mode tensors column-wise with the same sigmoid weights as in 1D
  — the weight depends on the projectile energy only, so the blend
  commutes with the Hankel transform and is exact per mode.
- This supersedes the previously postponed "hybrid kappa-window" design
  (1D tables at high energy coupled to a 2D low-energy window), which is
  dropped. The historical blend semantics are unchanged: the HE model
  defines the channel set, LE-only channels are not carried.
- Requesting a model that a database does not contain still fails with
  the explicit available-model listing.

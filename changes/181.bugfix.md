Fixed several defects in the new tabulated atmospheres.  The MSIS blend weights
ran backwards, so ``top_extension="msis*"`` introduced a density step at the
bottom of the blend instead of removing the one at the top of the table, and a
table short enough to clamp the blend to a single level divided by zero.  The
extension no longer raises ``TypeError`` when neither ``season`` nor ``doy``
is given, accepts the ``[0, 360)`` longitudes the table format stores, and is
evaluated over the shower impact point rather than over the detector for
:class:`~MCEq.geometry.density_profiles.TabulatedLocationCentered`.
Bilinear sampling now interpolates across the 360/0 seam of a global grid whose
longitude axis starts above zero, and ``get_pressure`` follows the density
through both profile extensions instead of staying flat.  Pressure inside the
MSIS blend band still comes from the table alone.  ``AtmosphereTable.load_from_csv``'s
ragged-column error no longer recommends marking a gap with ``nan``, which the
loader's validity mask drops anyway; it now says to fill the gap with a finite
density instead.
:meth:`~MCEq.geometry.density_profiles.TabulatedLocationCentered.set_theta` now
reports a direction that leaves a regional grid in terms of the zenith and
azimuth the caller asked for and the impact point they put the shower at,
rather than only the bare latitude the table was read at.
``EarthsAtmosphere.set_h_obs`` no longer skips the density spline rebuild when
the current zenith angle is 0, which left a vertical profile describing the
previous observation level.
:class:`~MCEq.geometry.density_profiles.TabulatedAtmosphere` now completes its
column down to a level set by ``set_h_obs``, the way *surface_elevation_m*
already did at construction, instead of leaving the profile stopped at the
table's lowest row and the path below it ``nan``.

Fixed the atomic-mass unit in ``inverse_interaction_length``: the
conversion used the proton mass instead of m_u, shifting **all**
interaction lengths (and therefore fluxes and shower profiles) by
~0.7%. Numbers produced with earlier versions differ at that level.

Fixed the per-step atmospheric density means fed to the ETD2 kernels
on inclined trajectories: the sampler behind ``etd2_nonuniform_path``
integrated :math:`1/\rho(X)` on a log grid only up to
:math:`X = 1\,\mathrm{g/cm^2}` and linearly beyond. On near-horizontal
paths (:math:`X_{max} \sim 3\times10^4`) the linear sample
(~7 g/cm² per point) under-resolves :math:`X = 1..50\,\mathrm{g/cm^2}`
— still 80..35 km altitude, where :math:`1/\rho` spans decades —
producing per-step means wrong by factors 0.4–1.6 that imprinted a
coherent 10–25% bump–dip structure on **all** species' fluxes at
:math:`X \sim 5{-}40\,\mathrm{g/cm^2}` for zenith angles
:math:`\gtrsim 85^\circ`. The log sample now spans the whole depth
domain; per-step means agree with adaptive quadrature to
:math:`\lesssim 5\times10^{-6}` from vertical through exactly
horizontal paths for both CORSIKA and MSIS00 atmospheres, and
vertical results are unchanged.

Fixed a missing velocity factor in ``inverse_decay_length``: the decay
rate per unit path length divided by the total energy
:math:`E = E_{kin}+m` instead of the lab momentum
:math:`p = \sqrt{E^2 - m^2}`, dropping the :math:`1/\beta` factor and
so understating the decay of slow (:math:`\beta<1`) particles. The rate
is now :math:`m/(c\tau\,p)`, exact at all energies. The effect is
negligible for ultra-relativistic particles but grows near threshold
(e.g. the deficit scales as :math:`\approx (1-\beta)` for the
decay-only limit); it slightly increases low-energy lepton fluxes.

Fixed a crash in ``solve()`` for systems whose decay block is empty
(e.g. pure-EM cascades): the BSR kernel builder now zero-pads an empty
``dec_off`` to the correct dimension instead of producing a
shape-mismatched matrix.

The adaptive EM step cap now computes the spectral radius of the EM
block with a dense eigenvalue solve instead of a sparse/norm fallback:
ARPACK does not converge on this highly non-normal block and the matrix
norm overestimates the radius, which made ``enable_em`` runs take far
more steps than necessary (together with the recalibrated
``em_step_safety`` this reduces EM step counts by roughly 3x with
Xmax changes below 0.03 g/cm^2).

The batched path builder (``solve_fullsky`` / ``solve_batch``) now
restores the zenith/azimuth that were *active* before the call. It
previously restored the constructor-time ``theta_deg``, silently
resetting any angle set later via ``set_zenith_azimuth`` once a
full-sky solve had run.

The cuda fp32 pipeline (shared-path multi-RHS and carousel) now
computes the ETD2 diagonal factors in fp64 inside the fused kernel
(fp32 buffers, double arithmetic, cast on write). The fp32
``phi1 = (e-1)/hd`` / ``phi2 = (e-1-hd)/hd^2`` cancellations lost 3-7
digits around the Taylor-switch thresholds (phi2 error up to ~1e-1 on
real MCEq diagonals), which dominated the fp32 solve error (~1e-3 on
the carousel). With fp64-internal diagonals all three factors sit at
fp32 roundoff and the fp32 solve error drops to the fp32
state/SpMM-accumulation floor, for ~5% step cost on an RTX 3090.

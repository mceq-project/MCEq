Batched (multi-RHS) ETD2RK solves across all backends, unified behind
``MCEqRun.solve_batch(phi0, conditions=…)``. The batch members are the
columns of ``phi0`` and/or the entries of ``conditions`` (per-member
``zenith_deg`` / ``azimuth_deg`` / ``density_model``), so many primary
spectra or single-primary energies, many directions, and atmospheres
for different days/seasons all run in one call — any mix included.
Duplicate conditions (e.g. azimuth pixels of azimuth-independent
atmospheres, flagged by the new ``density_model.depends_on_azimuth``
attribute) share one integration path; heterogeneous batches are
scheduled through an LPT carousel of pipeline width ``carousel_K``,
and batches whose conditions collapse onto one path automatically take
the cheaper shared-path route (which also supports ``int_grid``
snapshots and the EM ρ-stack). ``MCEqRun.solve_fullsky(zenith_grid,
azimuth_grid, …)`` is now sugar over ``solve_batch`` (adding the
geomagnetic-cutoff handling and sky-grid bookkeeping);
``solve_multirhs`` remains as a thin deprecated alias.

Batched solves return an ``MCEqBatchResult``: it unpacks like the old
tuples for backwards compatibility, and adds per-column named-spectrum
extraction with the full ``get_solution`` semantics —
``res.get_solution("conv_numu", k=…/zenith=…/pixel=…)`` and
``res.skymap(name, E)`` — via the extraction backend shared with
``MCEqRun.get_solution``. Initial-state columns can be composed without
touching private attributes through ``MCEqRun.get_initial_state()``
and ``MCEqRun.initial_state({"E": …, "pdg_id"/"corsika_id": …}
/ {"spectrum": …, "pdg_id": …})``, which build and return a column
while leaving the instance state untouched. ``solve_fullsky`` warns
when a 2-D ``phi0`` suppresses an explicitly requested geomagnetic
cutoff.

All four backends are wired for both routes (``kernel_config`` ∈
``{numpy_etd2, accelerate_etd2, mkl_etd2, cuda_etd2}``); the SpMM
kernels for MKL (``mkl_sparse_d_mm`` / ``_s_mm``) and CUDA (eager
``cupyx.scipy.sparse @ dense_2d``) are new on this branch and ship in
fp32 + fp64. The fused ETD2 post-apply C kernels move out of the
Mac-only ``MCEq.spacc`` extension into a new platform-neutral
``MCEq.etd2_kernels`` extension built on all platforms. On SATORI
(RTX 3090) at SIBYLL21 dim 7986, ``cuda_etd2`` holds flat at
~0.024 ms/iter/RHS fp32 through K=256 (~1300× per-RHS over Mac
Accelerate fp64); full-sky 5×5 multipath runs at ~97 ms/pixel fp32
(9.3× over the numpy reference).
